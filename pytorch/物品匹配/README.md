# 多角度物品图像向量检索识别系统

## 1. 项目目标
新品/换包装后，怎么做到低成本、快速上线，同时识别稳定
料上新与换包装太快，领导要求换了包装后用户识别要立马识别到，所以我们采用这套方案，每个饮品我们都会拍十几二十几张图片甚至几十张图片然后形成特征库，然后用户拍照后，对其进行识别，然后匹配出饮品
构建一个基于图像特征向量和向量数据库的物品识别系统。

系统不要求每增加一种物品就重新训练一个分类模型，而是通过为已有物品建立多角度图像特征库，在识别阶段将待识别图片转换为特征向量，并通过向量相似度检索判断其最可能对应的物品。

---
## 流程

项目背景：由于饮品上新和包装更换频繁，如果采用传统分类模型，每次新增饮品或更换包装都需要重新训练和发布模型，成本较高。因此采用“饮品特征库 + 向量检索”的方式，使新品或新包装在采集图片并建立特征后即可快速支持识别。

整体流程：

饮品上新 / 饮品更换包装 → 采集该饮品多张参考图片（十几张、二十几张甚至几十张）→ 对参考图片进行预处理 → 使用特征提取模型提取每张图片的视觉 Feature → 将这些 Feature 与对应的饮品 ID 进行关联 → 将 Feature 存入饮品特征库。

用户识别时：用户拍摄一张饮品图片 → 对用户图片进行预处理 → 使用相同的特征提取模型提取 Feature → 将用户图片的 Feature 与饮品特征库中的 Feature 进行相似度检索 → 找到最相似的饮品 Feature → 根据该 Feature 关联的饮品 ID 找到对应饮品 → 返回最终识别结果。

因此整个系统可以概括为：

饮品入库：
饮品 → 多张参考图片 → Feature 提取 → 多个 Feature → 关联饮品 ID → 存入饮品特征库

用户识别：
用户拍照 → Feature 提取 → 特征库相似度检索 → 找到最相似 Feature → 获取对应饮品 ID → 返回识别结果

换包装时：
原饮品 ID 不变 → 采集新包装图片 → 提取新包装 Feature → 将新 Feature 关联到原饮品 ID → 更新特征库 → 用户即可识别新包装。

## 2. 核心思路

### 建库阶段

针对每一种物品拍摄多张不同角度的图片，例如：

```text
可口可乐
├── 正面
├── 左侧
├── 右侧
├── 背面
├── 45°角
└── 其他实际可能出现的角度
```

每张图片经过图像特征提取模型：

```text
物品图片
    ↓
Embedding Model
    ↓
特征向量
    ↓
向量数据库
```

同时保存该向量对应的物品类别、图片角度等元数据。

例如：

```text
vector          label       view
-----------------------------------
[...256维...]   可口可乐     front
[...256维...]   可口可乐     left
[...256维...]   可口可乐     right
[...256维...]   雪碧         front
[...256维...]   雪碧         back
```

## 3. 识别阶段

现场通过摄像头或其他方式获取待识别图片：

```text
待识别图片
    ↓
Embedding Model
    ↓
Query Feature
    ↓
向量数据库
    ↓
Top-K 相似向量
    ↓
根据相似度判断
    ↓
识别结果
```

例如：

```text
Query Image
    ↓
Embedding
    ↓
Vector Search
    ↓
Top-K

1. 可口可乐  similarity = 0.93
2. 可口可乐  similarity = 0.91
3. 可口可乐  similarity = 0.89
4. 雪碧      similarity = 0.62
5. 雪碧      similarity = 0.59
```

最终可以判断：

```text
识别结果：可口可乐
```

---

## 4. 多角度设计

同一种物品不应该只存一张标准图片。

实际识别过程中，物品可能以不同角度出现，因此数据库中应该保存同一种物品的多角度样本。

目标是让：

```text
同一种物品
不同角度
不同姿态
不同合理拍摄条件
        ↓
特征空间中仍然比较接近
```

而：

```text
不同物品
        ↓
特征空间中尽可能远离
```

因此，该系统的核心并不是简单的“图片分类”，而是：

> **学习一个能够表达物品视觉身份的特征空间。**

---

## 5. 与传统分类模型的区别

传统分类：

```text
图片
 ↓
分类模型
 ↓
可口可乐 / 雪碧 / 芬达 / ...
```

如果增加一种新物品：

```text
新增物品
 ↓
增加训练数据
 ↓
重新训练或微调模型
```

而本项目希望采用：

```text
图片
 ↓
Embedding Model
 ↓
特征向量
 ↓
向量数据库检索
 ↓
已有物品
```

新增物品时：

```text
新增物品
 ↓
拍摄多个角度
 ↓
提取特征
 ↓
写入向量数据库
```

尽可能避免频繁重新训练整个识别模型。

---

## 6. 未知类别 / 拒识

系统不能简单地认为：

> Top-1 最相似的结果就是识别结果。

例如：

```text
Query
 ↓
Top-1：可口可乐 similarity = 0.51
Top-2：雪碧     similarity = 0.49
Top-3：芬达     similarity = 0.47
```

虽然可口可乐是最相似的，但整体相似度可能不足以证明它就是可口可乐。

因此系统需要设计：

```text
相似度
   ↓
阈值判断
   ↓
├── 足够相似 → 识别为某种物品
│
└── 不够相似 → 未知物品 / 无法识别
```

这属于系统后期必须解决的**拒识（Open-set Recognition）问题**。

## 7. 技术路线

当前学习阶段：

```text
ResNet / 其他视觉模型
        ↓
Image Embedding
        ↓
直接计算向量距离
        ↓
Top-K 最近邻
```

后续逐步演进：

```text
直接距离计算
    ↓
FAISS
    ↓
大规模向量检索
    ↓
Milvus / 其他向量数据库
    ↓
工程化部署
```

需要注意：

> **Milvus 不是识别算法本身，而是负责大规模向量存储和相似度检索的基础设施。**

---

## 8. 当前项目最核心的问题

整个系统最终能否识别准确，关键不只是向量数据库，而是：
① 用 CNN 还是 ViT？
② 用预训练模型还是自己训练？
③ Feature 取哪一层？
④ Feature 是整图向量还是局部特征？
⑤ 怎么让“同饮品近、不同饮品远”？
⑥ 换包装后，Feature 为什么还能匹配？
### 如何获得好的 Embedding？

需要让模型学习到：

```text
同一种物品：
不同角度 / 不同姿态 / 合理光照变化
        ↓
特征向量距离较近
```

同时：

```text
不同物品
        ↓
特征向量距离较远
```

因此后续需要重点研究：

* 使用什么特征提取模型
* 使用 ImageNet 预训练特征是否足够
* 是否需要针对物品数据进行微调
* 如何处理不同角度
* 如何处理背景变化
* 如何处理光照变化
* 如何确定相似度阈值
* 如何处理数据库中不存在的物品

---

## 9. 项目最终目标

最终形成一个：

```text
                物品图片
                   ↓
              图像特征模型
                   ↓
              Feature Vector
                   ↓
            ┌──────┴──────┐
            ↓             ↓
       已知物品库       相似度检索
            │             │
            └──────┬──────┘
                   ↓
              Top-K Results
                   ↓
             相似度 + 阈值
                   ↓
        ┌──────────┴──────────┐
        ↓                     ↓
     已知物品              未知物品
        ↓                     ↓
    返回物品类别           拒识
```

目标是实现一个支持**多角度物品样本、向量检索、动态增加物品类别以及未知类别拒识**的图像识别系统。
