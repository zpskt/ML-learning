### 2. 训练核心参数：Epochs

### 2.1 `epochs` 值如何确定？
`epochs` 代表模型完整遍历整个数据集的次数。其值需根据数据集大小动态调整，并配合早停机制。

| 数据集规模 | `epochs` 建议起点 | 策略 |
| :--- | :--- | :--- |
| 几百张图片 | 100 | 开启早停，观察验证集损失 |
| 几千张图片 | 150 ~ 200 | 开启早停，观察验证集损失 |
| 上万张图片 | 200 ~ 300 | 开启早停，观察验证集损失 |

### 2.2 分析 `E_best`（最佳迭代轮次）的价值
`E_best` 不是最终目标，而是一个用于诊断和优化训练过程的 **“探针”**。

- **判断超参数（如学习率）**：
    - `E_best` **过大**（如 > 500）：模型收敛慢，可能 **学习率设置过小**。
    - `E_best` **过小**（如 < 20）：模型快速陷入局部最优，可能 **学习率设置过大**，或模型容量远超数据集复杂度。
- **调节早停（`patience`）**：`patience` 值可设为 `E_best` 的 **10%~20%**，实现更高效的训练。
- **诊断数据与模型匹配度**：
    - `E_best` 过小：模型容量过大或数据集过于简单，易**过拟合**。
    - `E_best` 过大：模型容量不足或数据质量差（噪声多），易**欠拟合**。
- **评估新策略**：通过对比 `E_best`、损失曲线和最高 `mAP` 的变化，判断参数调整（如修改学习率、数据增强）是否有效。

### 2.3 组合观察 `E_best` 与损失曲线
| 观察到的组合 | 诊断结论 |
| :--- | :--- |
| `E_best` 小，`train_loss` 小，`val_loss` 大 | 🚨 过拟合，模型泛化能力差 |
| `E_best` 大，`train_loss` 大，`val_loss` 大 | 🚨 欠拟合，模型训练不理想 |
| `E_best` 大，`train_loss` 下降，`val_loss` 波动 | 模型或数据不稳定，尝试调节 `batch_size` 或数据增强 |

### 3. 训练监控：核心指标解读

#### 3.1 关键损失与性能指标
训练日志和 `results.csv` 中的指标是诊断模型状态的“仪表盘”。

| 参数名称 | 衡量什么？ | 理想趋势 | 单独显示的问题 |
| :--- | :--- | :--- | :--- |
| `train/box_loss` | 预测框与真实框的位置差距 | **持续下降**，趋于平稳 | 若震荡或上升：学习率过大，或数据有噪声 |
| `train/cls_loss` | 预测类别与真实类别的差距 | **持续下降**，趋于平稳 | 若下降缓慢：学习率偏小；若震荡：类别难区分 |
| `val/box_loss` | 验证集上，预测框的位置差距 | **下降后平稳**，始终低于训练损失 | 若开始上升：🚨 **过拟合的强烈信号** |
| `val/cls_loss` | 验证集上，预测类别的差距 | **下降后平稳**，始终低于训练损失 | 若开始上升：🚨 **过拟合**或验证集分布与训练集差异大 |
| `lr/pg0`, `lr/pg1`, `lr/pg2` | 不同参数组的实际学习率 | 按设定策略（如余弦退火）**规律变化** | 若不变：调度器未生效；若震荡异常：优化器设置问题 |
| `metrics/mAP50(B)` | 宽松标准（IoU=0.5）下的平均精度 | **持续上升**，趋于平稳 | 若停滞或下降：模型收敛或开始过拟合 |
| `metrics/mAP50-95(B)` | 严格标准（多IoU平均）下的平均精度 | **持续上升**，趋于平稳 | 若停滞：定位能力达瓶颈；若下降：严重过拟合 |

### 3.2 组合诊断：常见问题与解决方案

| 观察到的组合现象 | 诊断结论 | 解决方案 |
| :--- | :--- | :--- |
| `train/box_loss` 持续下降，但 `val/box_loss` 先降后升 | 🚨 **严重过拟合** | 1. 增加数据增强强度。<br>2. 引入权重衰减 (`weight_decay`) 或早停 (`patience`)。<br>3. 简化模型（如 `yolo26m` → `yolo26s`）。 |
| `train/cls_loss` 和 `val/cls_loss` 都很高且不下降 | 🚨 **欠拟合** | 1. 提高学习率 (`lr0`) 或增加 `epochs`。<br>2. 检查数据标签是否有误。<br>3. 增加模型复杂度。 |
| `lr/pg0` 急剧下降，但 `mAP50-95` 早早停滞 | 学习率衰减过快 | 调整学习率调度参数，如使用 `cos_lr=True` 或增大 `lrf`。 |
| `mAP50` 很高，但 `mAP50-95` 较低 | 定位不够精准 | 1. 增加损失函数中 `box` 损失的权重。<br>2. 尝试更高分辨率的输入 (`imgsz`)。 |
| 训练损失下降，但验证 `mAP` 不升 | 验证集与训练集分布不一致，或数据格式有误 | 1. 检查 `data.yaml` 中验证集路径。<br>2. 可视化验证集标注，确认加载正确。 |
| 损失值震荡剧烈，且 `mAP` 波动大 | 学习率过高，或 `batch_size` 太小 | 1. 降低学习率 (`lr0`)。<br>2. 增大 `batch_size`（受显存限制）。 |

### 4. 训练结果图详解

训练完成后，`runs/` 目录下会生成一系列用于分析和调优的图表。

### 4.1 `BoxF1_curve.png`：寻找最佳置信度阈值
- **作用**：展示 **F1 分数**（精确率与召回率的调和平均数）随 **置信度阈值** 变化的曲线。
- **用途**：帮助你找到精确率和召回率之间的**最佳平衡点**。
    - 阈值低 → 误报（假阳性）增多。
    - 阈值高 → 漏报（假阴性）增多。
    - 曲线的最高点即为模型的最佳工作点。

### 4.2 `BoxP_curve.png`：精确率-置信度曲线
- **作用**：专注于模型的 **精确率**，即“找得准不准”，不关心召回率。
- **用途**：随着置信度阈值提高，精确率通常上升。适用于**高精度优先**的场景（如医疗、安防），通过提高阈值来减少误报。

### 4.3 `BoxPR_curve.png`：精确率-召回率曲线（核心）
- **作用**：目标检测中最综合的性能图谱。**曲线下的面积就是 `mAP` 值**，面积越大，模型综合性能越强。
- **用途**：
    - **评估综合实力**：曲线越贴近左上角（高召回、高精度），性能越好。
    - **为业务选点**：
        - 高精度场景（如医疗影像）：选曲线**左上**部分（如 Recall=0.4, Precision=1.0）。
        - 高召回场景（如安防监控）：选曲线**右下**部分（如 Recall=0.8, Precision=0.85）。
    - **对比模型**：曲线包围面积更大的模型，通常更好。

### 4.4 `BoxR_curve.png`：召回率-置信度曲线
- **作用**：展示模型的 **召回率**（找得全不全）随置信度阈值的变化。曲线从左上向右下下降。
- **用途**：**漏报控制工具**。
    - **设定最低召回率门槛**：若业务不能漏掉关键目标，利用此图反向查找所需阈值。
    - **评估捕捉上限**：X轴为0时的Y轴截距，代表理论最大召回率。
    - **诊断难捕捉类别**：曲线起点低或下降快的类别，需增加训练数据。
    - **协同决策**：与精确率-置信度曲线结合，权衡误报和漏报。

### 4.5 `confusion_matrix.png` 与 `confusion_matrix_normalized.png`：混淆矩阵
- **作用**：展示模型在**哪些类别上容易犯错**，是直观的“错题本”。
- **`confusion_matrix.png`**：显示错误的具体**数量**，适合发现数据量大的类别的绝对错误。
- **`confusion_matrix_normalized.png`**：显示错误的**比例**（每行和为1），特别适合发现**小样本类别**的严重错误比例。
- **用途**：
    - 对比主对角线数字，找出识别能力弱的类别。
    - 观察非对角线错误，发现易混淆的类别对（如猫和狗），并针对性补充数据。

| | 原始混淆矩阵 | 归一化混淆矩阵 |
| :--- | :--- | :--- |
| **显示内容** | 错误的具体**数量** | 错误的**比例** |
| **最佳用途** | 了解数据量大的类别的绝对错误数 | 发现小样本类别的严重错误比例 |
| **指导价值** | 适用于类别分布平衡时 | 特别适用于类别样本数不平衡时 |

### 4.6 `labels.jpg`：数据集可视化概览
- **作用**：检查训练数据本身的分布和质量，而非模型性能。回答“我的数据集长什么样？标注质量如何？”
- **用途**：
    - **发现标注偏差**：检查框的中心点是否集中于图像中央（位置偏差），或框的尺寸是否过小/过大（尺寸偏差）。
    - **诊断类别不平衡**：检查各类别标注框数量的柱状图。
    - **检查数据多样性**：评估图片亮度、对比度、场景是否单一。
- **改进方法**：
    - **位置偏差**：增加随机裁剪和平移增强。
    - **尺寸偏差**：增加随机缩放或马赛克（Mosaic）增强。
    - **类别不平衡**：对少样本类别进行过采样或更强数据增强。

### 4.7 `results.png`：训练过程汇总图
- **作用**：包含上述所有关键指标（损失、精确率、召回率、mAP）随 `epoch` 变化的曲线，是判断训练是否健康的第一手资料。

## 预测阶段
预测阶段，需要将图片路径传入predict.py中，即可看到预测结果。yolo模型支持多种方式，网络连接，本地视频，视频流，图片等。
### 预测参数详解
https://docs.ultralytics.com/zh/modes/predict#%E5%9B%BA%E5%AE%9A%E5%B0%BA%E5%AF%B8%E4%B8%8E%E6%9C%80%E5%B0%8F%E7%9F%A9%E5%BD%A2-rect

#### 1. 置信度conf
模型会返回所有预测框，但是只保留置信度大于conf的预测框。
高精度场景，conf设置高一些。高召回场景，conf设置低一些。
#### 2. rect是否矩形填充
默认为True，表示将预测框填充为矩形，是 YOLO 推理中一个能显著影响速度和精度平衡的重要设置。它控制着图像在送入模型前，如何被缩放和填充。
YOLO 模型需要处理固定尺寸（如 640x640）的输入张量。但你的原始图片可能是 1920x1080、800x600 等五花八门的尺寸。因此，在推理前，必须对图片进行预处理。
设置为true：
这是 YOLO 为了提升速度而设计的优化策略。它的工作流程如下：
1等比例缩放：首先，将图片的长边缩放到你设定的 imgsz（比如 640），短边则按相同比例缩放。此时图片尺寸变为 640 x 短边缩放后尺寸（比如 640x360）。
2最小矩形填充：为了满足模型输入要求，它不会直接把图片填充到 640x640，而是只填充到最近的步幅（stride）倍数（通常是 32 的倍数）。在上面的例子里，640x360 会被填充到 640x384（因为 384 是 32 的倍数）。
3条件限制：这个优化要求同一批次（batch）里的所有图片，在缩放后必须具有相同的形状。如果图片尺寸差异很大，系统会自动退回到完整填充模式。
设置为false：
1等比例缩放：同样先将长边缩放到 imgsz。
2完整填充：无论图片原始比例如何，都强制将短边填充到 imgsz。640x360 的图片会被直接填充到 640x640。

在实际中如何选择？
你的场景	建议设置	原因
日常推理、本地测试	rect=True（默认）	速度更快，效果无差异。
需要导出模型（ONNX、TensorRT）	rect=False	导出的模型通常需要固定的输入尺寸（如 1x3x640x640）。
使用 Triton 等推理服务器	视部署框架要求而定	有些框架支持动态尺寸，有些不支持。
批处理图片尺寸差异极大	两者皆可（系统会自动退避）	当同一批次中图片尺寸差异过大时，rect=True 会自动退化为完整填充。
ps： 如果你意图商用，最后导出onnx等，那么设置 rect=False 的目的，不是为了在 ONNX 文件里记录这个参数，而是为了确保“导出 ONNX 模型时的推理行为”与“后续部署时使用 ONNX 模型进行推理的预期行为”保持一致。

## 核心推理参数

| 参数名 | 它是干什么的？                                                  | 调大/调高的直接影响 | 调小/调低的直接影响 | 实际场景设置建议 |
| :--- |:---------------------------------------------------------| :--- | :--- | :--- |
| **`conf`** | **置信度阈值**。只显示模型“信心”超过此值的检测结果。                            | 误报减少（更精准），但漏报增多（可能错过目标）。 | 漏报减少（更全面），但误报增多（可能检测错误）。 | **高精度场景（安检、医疗）**：设 `0.7` - `0.9`。<br>**高召回场景（监控、搜救）**：设 `0.3` - `0.5`。<br>**一般场景**：从 `0.25` 或 `0.5` 开始调试。 |
| **`iou`** | **非极大抑制 (NMS) 的 IoU 阈值**。重复判定分数线。用于消除同一物体周围的多个重复框。值越高，越允许框之间重叠。 | 同一物体周围保留更多重叠框（重复检测增多）。 | 同一物体周围框合并得更彻底（可能漏掉挨得很近的不同物体）。 | **物体稀疏、独立**：用默认 `0.45`。<br>**物体密集、紧挨着**（如人群、货架）：可尝试 `0.3` - `0.4`，避免合并不同物体的框。 |
| **`imgsz`** | **输入图像尺寸**。将输入图像缩放到此尺寸后再推理。                              | 检测精度可能提升（尤其对小物体），但推理速度变慢，显存占用增加。 | 推理速度变快，资源占用少，但可能丢失小物体细节。 | **追求速度**：设 `320` 或 `416`。<br>**追求精度**：设 `640` 或 `768`（需显存支持）。<br>**遵循模型训练尺寸**：与训练时 `imgsz` 一致效果最好。 |
| **`max_det`** | **每张图片最大检测数**。模型最多输出多少个检测框。                              | 允许检测出更多目标（可能包含一些低置信度的）。 | 限制检测数量，加快后处理速度。 | **一般场景**：默认 `300` 足够。<br>**密集场景**（如人群计数）：可调高至 `500` 或 `1000`。<br>**追求极速**：可调低至 `100`。 |
| **`device`** | **推理设备**。指定使用 CPU 还是 GPU。                                | 使用 GPU (`device=0`)：速度极快。 | 使用 CPU (`device=cpu`)：速度慢，但兼容性好。 | **有 NVIDIA GPU**：优先设 `device=0`。<br>**无 GPU 或兼容性问题**：设 `device=cpu`。 |
| **`classes`** | **过滤类别**。一个列表，只检测指定的类别 ID。                               | 只关注你感兴趣的物体，减少误报，提升速度。 | 检测所有类别，更全面。 | **明确目标**：如只需检测“人”和“车”，设 `classes=[0, 2]`。<br>**通用检测**：不设置此参数。 |
| **`half`** | **半精度推理 (FP16)**。使用 16 位浮点数进行计算。                         | 大幅提升推理速度，减少显存占用（在支持的 GPU 上）。 | 使用全精度 (FP32)，精度略高，但速度慢。 | **速度优先**：在 Tesla T4, RTX 系列等 GPU 上设为 `True`。<br>**精度优先或 GPU 不支持**：设为 `False`。 |
| **`verbose`** | **详细输出**。是否在终端打印推理日志（如速度、结果）。                            | 设为 `True` 时，会打印详细日志，方便调试。 | 设为 `False` 时，终端更干净。 | **调试阶段**：设 `True`。<br>**部署/生产环境**：设 `False`。 |

## 实战组合策略
