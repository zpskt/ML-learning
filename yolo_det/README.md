#### 常见点
1. epochs值大小如何确定？
 默认根据数据集的大小，几百张图片就设置100，几千张就设置150~200，超过万上设置200~300.然后利用早停机制和人工观察验证集损失来判断迭代次数。
2. 得到epochs合适的值有什么用么？
就像医生看病是多个指标一块看的。通过epochs可以辅助决策，主要有以下几点：
2.1 判断超参数
学习率是直接影响epoch的最大因素：e_best比常规数据大，说明模型走了太多弯路，学习率设置的太小。e_best比常规数据小，说明模型走到局部最低，不是全局最低，说明学习率过大，导致模型步子太大，
到了某一个局部最低。e_best是常规大小，损失曲线稳步下滑，这是最理想的状态。
2.2 调节早停耐心值
可以根据e_best的设置，来调节早停的耐心值。一般是e_best的10%~20%。 耐心值可以和学习率联动调节，有的时候模型进度迟滞，可以先调节学习率，然后再早停。
2.3 判断模型和数据集是否匹配
所有的训练都有正常的迭代论述，一般都是150-300之间。 如果很小（ex:20轮）就到最佳，可能原因有两个：1 模型太聪明，相对于数据集来说，可能模型不需要怎么训练就能记住所有训练样本 2 数据集太小，太相似，模型很快就能掌握所有模式。
这两种都算模型大材小用，容易陷入过拟合。一般做法是，换一个更小的模型，或者增加数据集。如果很大（ex:>500）,说明损失下降的非常慢，需要换成更大的模型，或者检查数据质量，清理错误标注，再或者增加学习率。
e_best一般都和损失一起组合观察。
e小，train_loss小，val_loss大，说明训练数据集过拟合，一遇到新数据就不行了。e大，train_loss大，val_loss大，说明模型训练不理想，尝试加速学习，调节数据质量。
e大，train_loss下降，val_loss波动，说明模型或者数据不稳定，可能数据多样性高，模型对数据变化敏感，尝试调节batch_size或者数据增强。
2.4 用e评估新的训练策略
主要就观察e，损失，最大精确度三者变化，就知道你调节参数（lr）以后是变好还是变坏

#### 参数观察
参数名称	衡量什么？	理想趋势	单独显示的问题
train/box_loss	训练集上，预测框与真实框的位置差距。	持续下降，并趋于平稳。	若震荡或上升：学习率可能过大，或数据有噪声。
train/cls_loss	训练集上，预测类别与真实类别的差距。	持续下降，并趋于平稳。	若下降缓慢：学习率可能偏小；若震荡：类别可能难以区分。
val/box_loss	验证集上，预测框的位置差距。	下降后趋于平稳，且始终低于训练损失。	若开始上升：🚨 过拟合的强烈信号。
val/cls_loss	验证集上，预测类别的差距。	下降后趋于平稳，且始终低于训练损失。	若开始上升：🚨 也指向过拟合，或验证集分布与训练集差异大。
lr/pg0, lr/pg1, lr/pg2	不同参数组（如backbone、head）的实际学习率。	按设定策略（如余弦退火）规律变化。	若不变：学习率调度器可能未生效；若震荡异常：优化器设置可能有问题。
metrics/mAP50(B)	宽松标准下的平均精度。	持续上升，最终趋于平稳。	若停滞或下降：模型可能已收敛，或开始过拟合。
metrics/mAP50-95(B)	严格标准下的平均精度（最核心指标）。	持续上升，最终趋于平稳。	若停滞：模型定位能力已达瓶颈；若下降：严重过拟合。


🔍 组合分析：参数如何协同工作，暴露核心问题？
观察到的组合现象	诊断结论	解决方案
train/box_loss 持续下降，但 val/box_loss 先降后升	🚨 严重过拟合。模型在“背诵”训练集，但无法泛化到新数据。	1. 增加数据增强强度。
2. 引入 权重衰减（weight_decay）或 早停（patience）。
3. 简化模型（如从yolo26m换为yolo26s）。
train/cls_loss 和 val/cls_loss 都很高且不下降	🚨 欠拟合。模型未能学到有效特征。	1. 提高学习率（lr0）或增加训练轮数（epochs）。
2. 检查数据标签是否有误。
3. 考虑增加模型复杂度。
lr/pg0 急剧下降，但 mAP50-95 早早停滞	学习率衰减过快，模型还在“爬山”但步子已太小。	调整学习率调度参数，如使用 cos_lr=True 或增大 lrf（最终学习率因子）。
mAP50 很高（如 >0.9），但 mAP50-95 较低（如 <0.5）	模型能大概找到目标，但定位不够精准，框与物体边缘贴合差。	1. 在损失函数中增加 box 损失的权重。
2. 尝试更高分辨率的输入（imgsz）。
所有训练损失都在下降，但 验证指标 (mAP) 从一开始就不升	数据验证集和训练集分布不一致，或数据格式有误。	1. 检查 data.yaml 中验证集路径是否正确。
2. 可视化验证集的标注，确认是否正确加载。
损失值震荡剧烈，且 mAP 也波动大	学习率设置过高，或批次大小（batch_size）太小导致梯度不稳定。	1. 降低学习率（lr0）。
2. 增大 batch_size（受显存限制）。

#### 结果图分析
1. BoxF1_curve.png
  这张图的核心是展示 F1 分数（精确率和召回率的调和平均数）如何随 置信度阈值 的变化而变化。
拿到这张 BoxF1_curve.png 图，你完全可以把它当作一个“性能调优工具”，用来指导你把模型部署到**实际场景**中。
你训练好的模型在预测时，会为每一个检测到的物体输出一个“信心分数”（0到1之间）。你可以在代码里设置一个门槛（conf 参数），只显示信心分数高于这个值的检测结果。
门槛设低了：模型会把很多“拿不准”的东西也框出来，导致误报（假阳性）增多。
门槛设高了：模型会变得很“谨慎”，只框出它特别确定的东西，导致漏报（假阴性）增多。
而 BoxF1_curve 图就是帮你在这两者之间找到最佳平衡点的“导航图”。
2. BoxP_Curve.png
 这个只看准确率，就是关注找的准不准，不关心找的全不全。通常，随着置信度阈值的提高，精确率也会上升。因为门槛越高，模型只输出最有把握的结果，误报自然减少。
 同样这个也是为了告诉你最佳现实平衡点，你可以看看是否准确率是第一优先级（医疗、安全等领域）
3. BoxPR_curve.png
这张 BoxPR_curve.png 图（精确率-召回率曲线，Precision-Recall Curve）是目标检测里最核心、最综合的性能图谱之一。这张图最根本的用途，是计算模型的 mAP（平均精度均值）。你之前看到的 mAP@0.5 或 mAP@0.5:0.95 这些关键数值，就是基于这条曲线下的面积计算得出的。曲线下的面积越大，模型的 mAP 就越高，综合性能就越强。
🎯 你可以用这张图来做什么？
评估模型的“综合实力”：这是最直接的用途。通过观察曲线形状，你可以定性判断模型性能：

理想曲线：应该紧贴左上角（Recall=0, Precision=1）然后缓慢下降。你的曲线在召回率达到0.4之前都保持1.00，这是很好的信号。

差劲曲线：如果曲线从开始就急速下降，说明模型错误率很高。

为特定业务选择“工作点”：你可以根据业务对“误报”和“漏报”的容忍度，在曲线上选择一个工作点（即对应的置信度阈值）。

高精度场景（如医疗影像）：你会选择曲线靠近左上角的部分（如Recall=0.4, Precision=1.0的点），确保极少误报。

高召回场景（如安防监控）：你会选择曲线靠近右下角的部分（如Recall=0.8, Precision=0.85的点），确保尽可能不漏掉目标。

对比不同模型的性能：当你训练了多个模型变体后，可以把它们的PR曲线绘制在同一张图上。曲线包围面积更大的那个模型，通常就是更好的模型，这比单独看某个点更全面、更可靠。
